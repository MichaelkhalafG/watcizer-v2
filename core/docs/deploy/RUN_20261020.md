## A PROPOSAL, not a decision — previewing the banner hero on live Watchizer

Michael asked for options, not a choice, and nothing below is built. **Nothing in the backlog decides this** (checked:
`POST_CUTOVER_BACKLOG.md` has no row about previewing a home hero), so it is genuinely open.

One thing to say first, because it changes what a preview is *for*: whether the hero **works** on Watchizer is no
longer in question — it was rendered in Watchizer's own app and measured (3 slides, 2 visible per device, dots,
arrows, drag, the non-first banner screenshotted). What a preview buys is a judgement about **the artwork**: does
this picture, cropped to this shape, look right above Watchizer's category row. That is worth much less engineering
than "is it safe", which is already answered.

**A — a query flag the page reads on the client. ~1 line.** `/?hero=banner` makes that one visitor's page draw the
banner hero; nobody else is affected and nothing is stored. The server still sends the 3D page, so the swap happens
after hydration — a visible flip. The URL is guessable, so it wants a `noindex` on that query or it may be crawled.
Cheapest by a wide margin, and enough to judge artwork.

**B — the same flag, read on the SERVER.** `page.jsx` reads `searchParams` and passes the mode down, so there is no
flip. The cost is real: a page that reads `searchParams` **opts out of ISR for that request**, so this must be
scoped to the flag's presence only, and it is easy to get wrong on a page that is live and cached.

**C — a signed preview cookie, set from the dashboard. Half a day, maybe more.** A "Preview on the shop" button
beside the switch sets a short-lived signed cookie on the storefront's domain; the app's middleware reads it and
renders the banner hero server-side. No guessable URL, no flash, it expires by itself, and it is the right answer
**if previewing becomes a routine thing** for other settings too. It needs a secret shared between core and the app
and a middleware branch on the live shop, which is the part I would want reviewed carefully.

**D — flip it at a quiet hour and watch. Zero code.** The switch is one dropdown and it is reversible in seconds;
the only lag is the shop's own ISR window (up to 5 minutes) — and the dashboard says so on the panel. Real shoppers
would see it for those minutes.

**If asked, I would say: A now, D as the honest fallback, C only if previewing becomes routine.** B buys little over
A and touches the caching of a live page, which is the one thing here with a real downside.
