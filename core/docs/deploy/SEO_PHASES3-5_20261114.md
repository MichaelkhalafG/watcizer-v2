## The order (the whole deploy, Phases 1–5)

1. **Merge** bf-wheel and pickup (yours). Then build the archive from the merged branch:
   - `npm run build` in core (the dashboard bundle: the Reviews screen must be in the manifest; the script checks);
   - the tar, with the exclude list.
2. **Before running:** run the whole core suite once on a FRESH copy of production with its credentials blanked
   (memory note "Scratch copy: encrypted credentials"). This run's copy had drifted (U30).
3. **Upload** the archive, `seo1-contact-data.sql`, `seo1-followers.sql`, then run (yours):
   `TAG=a BLOG_START=YYYY-MM-DD bash ~/deploy-seo-combined-20261114.sh`.
   BLOG_START is the first publication day, Cairo; the default is tomorrow. Leave EXTRA_MIGRATIONS / EXTRA_REQUIRED
   for the merged branches as before. What runs, in order:
   - steps 0–9 as in Phase 1, now with nine migrations (the schema gate expects 23 new columns, 4 new tables) and the
     review e-mails proved OFF;
   - **10b** `seo:load-copy` then `seo:gate` (at least 4 page texts passed);
   - **10c** `blog:import` batch 1 for each shop, dry then `--apply` (nothing scheduled before now: gate);
   - 11–13 as before;
   - **14** adds: an unknown review link → 404; `blog:publish-due` → "nothing due"; `reviews:request --no-mail`;
     `seo:weekly-report`.
4. **Push main** (yours). Hostinger rebuilds both shops. Confirm each build finished, then hard-reload before
   checking.
5. **The live checks** (below).
6. **IndexNow on:** `bash ~/seo-indexnow-on-20261114.sh`. Then resubmit both sitemaps in Search Console and Bing; the
   feeds can be added there too.
7. **When you choose** (each: the .env line, then `php artisan config:cache`):
   - `GSC_SERVICE_ACCOUNT_JSON=…`: the JSON on one line, or a path. Add the service account's e-mail as a user of
     both Search Console properties.
   - `BING_WEBMASTER_API_KEY=…`
   - `REVIEW_REQUESTS_ENABLED=true` (W6).

## Undo, per part

- **The whole core deploy:** as Phase 1. The code from the before-snapshot, then `seo-combined-undo-db.sql` with
  `--force`. It now also removes:
  - the imported, never-published articles;
  - the landing page texts;
  - the blog settings;
  - migrations 000006–000008 (columns and tables).
  The two brand texts `seo:load-copy` replaced come back from the 3b dump if wanted. Then the caches.
- **Only the articles:** pause both shops on the dashboard (nothing publishes). Or delete the scheduled ones:
  `DELETE t FROM core_blog_translations t JOIN core_blogs b ON b.id = t.blog_id WHERE b.status = 'scheduled'; DELETE FROM core_blogs WHERE status = 'scheduled';`
- **Only the reviews:** leave REVIEW_REQUESTS_ENABLED off. Reject reviews on the Reviews screen; a rejected one
  disappears from the product page at the next cache flush.
- **Only the safety pause:** the storefront screen's switch.
- **The storefronts:** revert the push (Hostinger rebuilds). The pages added here simply disappear. Core keeps
  answering the old shapes (`blocks`, `related`, `reviews` are additions).
