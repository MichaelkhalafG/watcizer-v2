## Undo

In this order. The data steps FIRST, while the new code is in place:

1. `php -d memory_limit=3072M artisan catalog:load-descriptions - --undo`
2. `php artisan reviews:branches --undo`
3. `php artisan blog:heroes --undo`
4. The batch-2 articles, while still scheduled (ids in `~/release-20261118-a/batch2-ids.tsv`):
   `mysql ... -e "DELETE t FROM core_blog_translations t JOIN core_blogs b ON b.id = t.blog_id WHERE b.id IN (<ids>) AND b.status = 'scheduled'; DELETE FROM core_blogs WHERE id IN (<ids>) AND status = 'scheduled';"`
5. The page texts: restore `core_seo_texts` from the dump:
   `zcat ~/db-before-20261118-release-a.sql.gz | sed -n '/^-- Table structure for table .core_seo_texts./,/^-- Table structure for table /p' | mysql ...`
6. `php artisan migrate:rollback --step=2`. If a guest review was written after the deploy, its `order_id` is empty and
   the rollback cannot make the column required again: delete those reviews first
   (`DELETE FROM product_reviews WHERE source <> 'request'`), knowing they are lost.
7. Then the code and `.htaccess` from the before-snapshot, then `config:cache`, `route:cache`, `view:clear` and
   `catalog:warm`. The shops: revert the merge on `main` and push.
