## 3. Deploy core (runbook §2), then the migration

### 3.1 Before the migration — look, do not change

```bash
php artisan migrate:status | tail -5
```

**Must print** `2026_10_23_000000_orders_storefront_backfill ... Pending`.

```bash
php artisan migrate --pretend
```

**Must list exactly ONE migration name:** `2026_10_23_000000_orders_storefront_backfill`.

> **If it lists a SECOND name, STOP and do not run `migrate`.**
> A third name means production is behind on a migration from an earlier wave that nobody has run. Deploying
> it blind, at the same moment as a NOT NULL constraint, is two changes with one rollback. Write the name
> down, roll the core tar back to the previous release, and deal with it separately.

Record the number you are about to change, so §4 can be checked against it:

```sql
SELECT COUNT(*) FROM orders WHERE storefront_id IS NULL;
```

**Expected: 9.** If it is 0, the migration has already been run and §3.2 will be a no-op, which is safe. If it
is more than 9, new untagged orders have been written since 2026-10-20 — stop, and tell me, because the
backfill's proof (that every untagged order predates the storefronts) would no longer hold.


**Must print** `2026_10_23_000000_orders_storefront_backfill .......... DONE` and nothing else.

## 5. If you have to roll the migration back

**`php artisan migrate:rollback` will refuse.** That is deliberate and is not a fault. Use this, which was
run and verified on a copy of production:

```sql
-- the ids come from storage/app/orders_storefront_backfill.json
ALTER TABLE `orders` MODIFY `storefront_id` BIGINT UNSIGNED NULL;
UPDATE `orders` SET `storefront_id` = NULL WHERE `id` IN (1,2,3,4,5,6,7,8,9);
DELETE FROM `core_migrations` WHERE `migration` = '2026_10_23_000000_orders_storefront_backfill';
```

Then `php artisan config:cache`. Verified result: 9 rows null again, 20 on storefront 1, column nullable,
ledger row gone — the exact state before the migration.

**Do not** `UPDATE orders SET storefront_id = NULL WHERE storefront_id = 1`. That would untag every Watchizer
order ever placed. Only the nine recorded ids.

- The announcement strip's text no longer runs under the Facebook/Instagram icons.

### The dashboard

### Brand Fashion — prove it is unaffected
