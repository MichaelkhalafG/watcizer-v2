## 2. What ships, and what each needs from you

### Step A — the paid order that was left cancelled
Cause: a declined attempt cancelled the order and released its stock at once; Paymob lets the customer retry inside
the same intention, and the success that followed met a cancelled order and was only recorded as a finding. Now a
decline cancels nothing (the unpaid window does, 60 minutes later, as for any abandoned order), and a success on an
order cancelled for non-payment reinstates it through the stock ledger. Where it cannot (stock gone, or the customer
already placed a newer order) the money is flagged: a red notice on the orders screen and on the order, and an e-mail
to the shop's admin address. `orders:reinstate-paid` repairs an order that is already stranded.

## 7. RECOMMENDATIONS taken without you (each reversible) and what needs you

Decisions taken, safest reversible option, in the order they matter:

1. **A decline waits for the 60-minute unpaid window** instead of cancelling at once. Alternative rejected: a short
   grace (5–10 minutes) — it only narrows the hole it leaves. Cost: a declined order holds its stock up to an hour.
2. **Only an order cancelled for non-payment is reinstated automatically.** One the team cancelled by hand is
   flagged, not revived (the command has `--cancelled-by-operator` for a deliberate repair).
3. **The wave-3 alias handler was not given reinstatement** — it is dead wherever the contract is live.
4. **The campaign's name is internal**; shoppers see "Flash sale" / "Hot deals". Say so if a campaign should carry
   its own title on the page.
5. **"Sold" counts every storefront's sales** of a campaign product — the stock is shared, so is the bar.
6. **The Campaign hero is offered to Watchizer only** (it is the Grand Prix banner). Brand Fashion chooses 3D or
   Banners. **Needs you** if Brand Fashion should have a campaign hero: it needs artwork and a brief.
7. **Side slots**: 960×500, one banner each, the same picture on phone and computer; on a phone they sit under the
   hero, side by side.
8. **Blend** = the photo's white background dissolves into the slider's colour. Right on light colours only; the
   dashboard says so.
9. **Category picture**: "most recent" = newest by `created_at`; only a visible, active, in-stock product with a
   photo counts, so a sold-out category shows no picture. Three states: own / automatic / none.
10. **Mega menu**: the rail is the top-level categories, the genders, Brands, On sale, New arrivals. The brand row
    under the tiles is "Brands in this section" — the brands with the most products in stock there — not "popular":
    there is no sales ranking to call a brand popular honestly. The featured card is the biggest real discount in
    stock, else the newest product, with its real lowest price. The phone keeps its drawer.
11. **Campaign pages are `noindex, follow`**: they exist all year and are empty outside a campaign.
12. **Hot Deals mode** is remembered in the browser for the campaign it was switched on for, and ends with it.
13. **Payment badges**: ordering by WhatsApp is not a way to pay and gets no badge; a badge without a picture shows
    the method's name; no card-scheme logo ships in the repository (third-party artwork — upload the official files).
14. **Watchizer's cart** shows the badges under the items, not in the summary: the summary is a sticky box with a
    height limit and seven badges pushed its last row into an inner scroll at 1440×900.
15. **Page texts**: the bullets of real specifics are read from each page's own listing when the seeder runs, and
    dated; "Good to know" and the questions are the same for pages of the same kind — a starting text.
16. **El Messiri is three font families** (Arabic, Latin, Latin-ext — Google's own files, byte for byte) joined by
    one CSS variable, rather than one merged file.

### 11.3 The `.avif` cache lifetime on the API host — five lines for you to add by hand

Measured on 2026-11-06, read-only, on both API hosts (`api.watchizereg.com`, `api.michaelkhalaf.com`): a `.webp` picture
is answered with `cache-control: public, max-age=604800` and an `expires` header seven days ahead; the `.avif` rendition
of the same picture is answered with **neither** (its `content-type: image/avif` is right — that is line 1 of the live
`.htaccess`). So a returning visitor's browser re-asks for every AVIF product photo. Production was not touched.

**The lines** — put them directly under line 1 of `~/domains/eleganceeg.com/core/public/.htaccess` (the file that
serves both API hosts), so the top of the file reads:

```apache
AddType image/avif .avif
# AVIF renditions: the same seven days the host gives WebP (2026-11-06)
<IfModule mod_expires.c>
ExpiresActive On
ExpiresByType image/avif "access plus 7 days"
</IfModule>
```

(line 1 is already there; the five lines after it are new: the file goes from 65 to **70** lines.)

**When:** after `deploy-part2-20261105.sh` has finished — its step 4 backs the live file up and step 5 restores it and
proves the hosts, and both expect the 65-line file. The script was made tolerant today, so a later run is not stopped by
your edit: it accepts 65 lines, or 70 with exactly one `ExpiresByType image/avif` line, and the block then rides in the
backup and is restored with it.

**Before you edit, keep a copy** (`cp .htaccess ~/htaccess-before-avif-$(date +%Y%m%d)`), then **check** — the query
string makes the CDN ask the origin instead of answering from its own copy:

```bash
curl -sI "https://api.watchizereg.com/Uploads_Images/Product_image/1791450946_2026-10-08_6ac75f421b814-160.avif?v=1" | grep -i -E '^(cache-control|expires|content-type)'
curl -sI "https://api.michaelkhalaf.com/Uploads_Images/Product_image/1790761271_2026-09-30_6abcd93777276-320.avif?v=1" | grep -i -E '^(cache-control|expires|content-type)'
curl -s -o /dev/null -w '%{http_code}\n' https://api.watchizereg.com/api/catalog/meta   # still 401: the allow-list is intact
```

Expected on the first two: `cache-control: public, max-age=604800`, an `expires` line, `content-type: image/avif` — the
same three a `.webp` gives today. **If the headers do not appear** (the host's server ignoring `mod_expires` in
`.htaccess` for this type — not something that could be tried from here), replace the four `mod_expires` lines with this
block, which sets the header itself, and check again:

```apache
<IfModule mod_headers.c>
<FilesMatch "\.avif$">
Header set Cache-Control "public, max-age=604800"
</FilesMatch>
</IfModule>
```

(that variant makes the file 71 lines; tell me and the next script's count follows.) **Undo:** delete the added lines,
or `cp` the copy back. A wrong line in `.htaccess` answers 500 on the whole host at once — the third `curl` above is the
check for that, and the copy is the way back.
